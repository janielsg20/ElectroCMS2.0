# M05.5 — Usar Puck visual history

**Fase propietaria:** F05 — Puck Visual Editor Core

## Por qué existe
Esta microfase existe para **Usar Puck visual history** dentro de la responsabilidad de `F05`: integrar Puck sin duplicar su editor. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Usar Puck visual history** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Puck`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCMS solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Packages/área de código
`editor-puck + studio/editor`

## Ubicación visual
Editor dentro del AppShell: Components/Pages/Outline a la izquierda, Canvas central, Inspector derecho.


## Precondiciones
- `M05.4` COMPLETADA.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Conecta Undo/Redo del Topbar al `history.back/forward/hasPast/hasFuture` público de Puck.
2. History de Puck pertenece a la sesión de edición; no es ProjectRevision.
3. Settings > Editor expone `visualHistoryLimit` con default seguro y rango limitado; no valores ilimitados.
4. Implementa `PuckHistoryPolicyAdapter`: observa la history pública y, al superar el límite, usa `setHistories`/`setHistoryIndex` para conservar la ventana reciente correcta sin cambiar el estado actual.
5. No serialices AppState/history de Puck dentro del ProjectDefinition para reanudar Undo entre sesiones.
6. Después de undo/redo sincroniza ElectroDocument y márcalo dirty para autosave incremental.
7. Al cambiar documento, no mezcles stacks de documentos distintos; usa lifecycle/initialHistory únicamente si una sesión necesita restaurar su stack en memoria.
8. Project revisions/cross-session restore pertenecen a F04 y nunca aparecen como botones Undo/Redo.
9. Prueba límite 1/default/max, edit/drag/delete, branch después de undo, save/reopen y confirma que el documento persiste aunque la nueva sesión comience con history limpio.
