# M15.3 — Refine useTable + TanStack DataView

**Fase propietaria:** F15 — Backend Builder con Refine y TanStack

## Por qué existe
Esta microfase existe para **Refine useTable + TanStack DataView** dentro de la responsabilidad de `F15`: resolver Backend con Refine/TanStack. Debe cerrar una capacidad concreta y no abrir un subsystem paralelo.

## Resultado exacto
Al cerrar esta microfase, **Refine useTable + TanStack DataView** debe existir como capacidad real, integrada y verificable. No se acepta placeholder ni una implementación paralela al engine.

## Engine owner
`Refine + TanStack + RHF`

### Regla
Antes de escribir código, consulta la API pública del engine. Si ya existe la capacidad, úsala. ElectroCMS solo debe aportar canonical mapping, configuración, UX, adapter, target semantics o exportación.

## Packages/área de código
`admin-refine + backend`

## Ubicación visual
Administrar > Backend; visual admin document and runtime configuration.


## Precondiciones
- `M15.2` COMPLETADA.
- Engine owner disponible detrás de su adapter.
- No existen errores P0/P1 de la dependencia inmediata.
- Tests existentes están verdes antes de modificar comportamiento.

## Implementación línea por línea
1. Usa Refine `useTable` para resource, filters, sorters, pagination, URL state y data lifecycle.
2. Usa TanStack Table para row model, columns, selection, visibility, order, sizing, pinning/grouping when configured.
3. `AdminDataViewDefinition` persiste solo configuration: columns, formats, available filters/actions/default view.
4. Runtime table state permanece controlled/local/TanStack; solo SavedView serializa filters/sort/visible/order/pageSize/pinning when selected.
5. Desktop renderiza semantic table; Mobile usa cards/list y NO necesita TanStack Table dependency si el target no la usa.
6. Virtualization se añade solo tras medición; usa TanStack Virtual si aplica, no custom virtualizer.
7. Bulk actions consumen selected record IDs.
8. Prueba 1000+ rows fixture con sort/filter/page/selection.
